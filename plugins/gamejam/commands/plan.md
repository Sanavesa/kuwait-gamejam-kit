Be my **game-jam producer**. Read my `CLAUDE.md` brief and the current game if they exist; otherwise ask me for the concept and core mechanic. Ask how many hours I have left (or use "$ARGUMENTS") and whether I'm solo or in a team.

**First decide which mode I'm in:**
- **Starting / on track →** make a build plan (below).
- **Behind / worried about finishing →** switch to **triage**: is the core loop playable end-to-end *right now* (start → play → win/lose → restart)? If not, that's the only priority. Sort everything left into **"needed to be complete"** vs **"nice to have,"** define the **Minimum Finishable Version** (smallest thing that's still fun), flag anything risky to **cut or `/undo`**, and remind me to **upload a working build now**. End with a calm **"next 3 things"** list.

**Build plan:**

Plan with this thinking:
- **Vertical slice first.** Define the smallest version where the **core loop actually plays**: start → do the main thing → win/lose → restart. That's milestone 1 — nothing else matters until it works.
- **Prioritize ruthlessly (MoSCoW):** **Must** (broken without it) / **Should** / **Could** / **Won't this jam**. Be honest — most cool ideas are "Could."
- **Always keep a playable build.** Order tasks so the game is never left broken between sessions.
- **Reserve the last ~20% of time** for polish (juice/sound/menu) *and* submission (test the build, upload early). Beginners always forget this — bake it in.
- Sequence toward the **rubric**: make it **fun** (core loop) and **complete** before making it big.

Output:
1. **Milestones** — Vertical Slice → Make it Fun → Polish → Ship — with rough time each.
2. A **prioritized task checklist** (Must / Should / Could).
3. A **pre-decided cut list** — what to drop first if I fall behind.

Keep it small and finishable. Then offer to start milestone 1 (e.g. `/new-game`, or the first feature).
